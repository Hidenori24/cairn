## C. 外に出すためのデータの書き換え

ユーザーの依頼により、サンプル（`golden/samples/`・`reference-js/data/samples/`・`reference-js/js/lib/sample.js`）から製品・社内を特定できる語を一般的な表現に置き換えた。

- 製品名（特定の機器の種類）→「組込み機器」「対象製品」
- 社内の開発手法を示す語（特定のコーディング規約名・テストの呼び方・機種の派生の呼び方）→ 一般的な表現
- プロジェクトのキーの例 → `DEV`（SPEC・JS版の画面の例も同じに変更）

置き換えは件名・説明・Epic Name の文字列だけで、日付・期間・依存関係などの計算に関わる値は変えていない。
golden は JS版のライブラリ（`sched.js`・`csvio.js`・`engine.js`）をそのまま使うスクリプトで作り直した（書き換える前の golden を1バイトも違わず再現できることを確かめてから使った）。このスクリプトは C-2 で削除した。

### C-2. JS版（reference-js/）の削除と git 履歴の作り直し（0.3.1）
ユーザーの依頼（「JS版は使わない」「exe だけあればよい」「git 履歴は丸ごと消して」）により、次を行った。
- `reference-js/`（JS版のソース）と、golden を JS版から作り直すスクリプト・CI の「golden の再現性」の手順を削除した。golden は以後、**C++ 版の出力と照合する固定の正解データ**で、JS版から作り直す手段はない（追加が要るときは、`rmcli` の出力を人が確かめてから足す）。
- 古い履歴を残さないよう、git の履歴を作り直した（ルートのコミットは 0.3.1 の内容）。
- SPEC.md 本文の `reference-js/…` への参照は、当時の確認先を示す記録として残した（0.2 に注記）。

### C-3. 追加時の値の引き継ぎ（0.4.0。Issue #14）
- 引き継ぎの設定は prefs の `inherit`（`on` と項目ごとの真偽）。既定は `on=false` で今までどおり。項目が空の元からは写さず、通知にも出さない。
- 元は「同じ階層に追加」なら直前の兄弟（追加位置の直前の課題）、「子を追加」なら親。最上位を末尾に足すときは元がないので引き継がない。
- 種別は設定に関わらず階層で決める（Epic の子は Task、それ以外は Sub-task）。「種別」をオンにした兄弟からの引き継ぎだけ、兄弟の種別を写す。期間も兄弟からだけ（親の期間は子の合計で決まるため）。
- 期限は画面に出ている「その課題自身の期限」を写す。Deadline 列の無い CSV では Due date を写す。
- 担当者を引き継ぐと担当者ごとの負荷が偏る。今回は設定の説明に注意を書くだけで、負荷の通知は出さない（Issue の「検討」）。
