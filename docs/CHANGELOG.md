### 作成日・更新日の自動記録
- **アプリで作った課題に作成日（Created）、中身を変えた課題に更新日（Updated）を自動で記録します**（#66）。統計の推移（バーンダウン・リードタイム・滞留日数）が、JIRA の CSV を取り込んだときだけでなく、アプリで作ったプロジェクトでも出ます（「CSV に Created の列がないので…」の注記が出なくなります）。
- **作成日**: 追加・子を追加・同じ階層に追加・アウトラインの貼り付け・テンプレートの適用・新しい後続を作る、のすべてで入ります。CSV／JSON の取り込み・置き換え・サンプルや雛形で作ったものには入れません（作成日が空のものも埋めません）。既存の課題へは埋め戻しません（嘘の履歴になるため）。
- **更新日**: 件名・状況・担当・優先度・日付・期間・見積り・依存・ラベル・説明・コメント・親・種別を変えたとき、変わった課題すべてに入ります（1 回の操作で複数の課題が変われば全部。依存はつないだ両端）。選択・表示・折りたたみ・兄弟の並べ替え・設定・添付／リンクの追加では変わりません。同じ日に何度編集しても同じ日付です。
- 日付は完了日と同じ決め方（今日と基準日の早い方）で、書式は `YYYY-MM-DD`。更新日の列の最初の値が JIRA の日時（`19/Oct/26 9:00 AM`）なら、その書式で書きます。元に戻す・やり直すと、作成日・更新日も一緒に戻ります。
- 記録は編集の入口（`Session::mutate`）の 1 か所で、編集の前後を比べて行います（`core/stamps`。UI 非依存）。個別のコマンドには書いていないので、書き忘れが出ません。推移（`core/trends`）が読む見出しの別名（`作成日`・`更新日` など）も共通にしました。
- 単体テスト（`tests/unit/test_stamps.cpp`）: 作成経路ごと・編集の種類ごと・変えない操作・列がないときの追加と空の揃え・既存の列（JIRA の書式・別名の見出し・他の未知の列の後ろ）・1 件もない CSV の書き出しが今までと同じバイト列（golden のサンプルの往復）・Undo/Redo・再オープン・複数課題を変える 1 操作・推移が出ること。UI の煙テスト: 新規プロジェクトで課題を作る → 編集 → 完了にする → 統計の推移が出る。
- 暫定判断は docs/spec-questions.md の B46。入れていない: 詳細パネルで作成日を手で入れる欄（別途）、既存の課題の作成日の埋め戻し、課題単位の複製（アプリにない）。

### 関連リンク
- **課題に関連リンク（URL・社内のファイル・フォルダ）を付けて、開ける**（#60）。添付（本体をコピーする）と違い、**場所を指すだけ**で何もコピーしない。詳細パネルの「添付」タブの中の別の節「リンク」（上が添付ファイル、下がリンク。新しいタブは作らない。タブの見出しにもリンクの数を出す）。平置きのプロジェクトにも付けられる（置き場が要らないため）
- **追加**: 場所（URL かパス）の入力欄と表示名（省略すると URL の「ホスト + 末尾の 2 区画」・ファイル名・フォルダ名）。「リンクを追加」か Enter。「**貼り付けて追加**」ボタンでクリップボードの各行を 1 行 1 リンクとして追加（20 行まで。断った行は件数と最初の理由だけを通知。行の中身は出さない）。`Ctrl+V` の既存の動き（子課題の貼り付け・画像の添付）は変えず、入力欄の中ではふつうに貼り付く。追加欄に「URL・パスがプロジェクトの設定ファイルに入ります」の注意
- **種類の自動判定**（`core/links.hpp` の `classifyLink`。文字列だけで決め、存在確認や I/O をしない）: Web（`http://` `https://`）・ファイル・フォルダ（`file://`・UNC `\\server\share\…`・ドライブ付き `C:\…`。末尾が `\` `/` ならフォルダ。共有のルート `\\server\share` もフォルダ）。**許可リスト**以外（`javascript:` `ms-msdt:` `data:` `vbscript:` `ftp:` `mailto:` など、デバイスのパス `\\?\` `\\.\`、`C:\a.txt:stream`、ID・パスワード入りの URL、`< > " | * ?`、右から左への上書きなどの制御文字、不正な UTF-8）は **Rejected**（理由つき。開かず、追加もしない）。形が分からないもの（空・相対パス・ふつうの文章）は Unknown。前後の空白・`"` `“”` `<>` の囲み（エクスプローラーの「パスのコピー」）・制御文字（改行を含む）・ゼロ幅の文字を取り除いて正規化し、Web はスキームを小文字に、URL の空白は `%20` にする。長さは URL 2,048 バイト・パス 1,024 バイトまで。`LinkKind` は `enum class` で、種類を足しやすい
- **一覧**: 種類のアイコン（Web=地球・ファイル・フォルダ。実行ファイルは警告の印）・表示名・場所（薄く）。**クリックで開く**。右クリックのメニュー: 開く／場所（フォルダ）を開く（ファイルのとき）／コピー／編集／削除／上へ／下へ。行の「開く」とごみ箱。編集は入力欄に入れて「保存」か「やめる」。載せて少し待つと、場所の全体
- **同じ課題の中の並べ替え**と、**別の課題へのドラッグ移動／Ctrl コピー**: 添付のドラッグの仕組み（`attachDrag`・`dropTargets`）をそのまま使う（`link` の印を足しただけ。Esc・ダイアログ・プロジェクトの切り替えでの取り消しも同じ）。同じ課題に同じ場所があれば移動・コピーは断る
- **開く**: `IPlatform::openLink(target, &error)`（Win32 は `ShellExecuteW`。プラットフォームも許可リストを確かめてから開く）。**Rejected は開かず理由を通知**。実行ファイル・スクリプト（`.exe` `.bat` `.ps1` `.lnk` など。**添付と同じ `isRiskyFile`**。`file://` は断片（`#`）を分け `%XX` を戻して判定・警告・親フォルダを同じ解析で行い、末尾の空白と「.」もすり抜けさせない）は添付と同じ警告ダイアログ（確認したら開く）。ファイル・UNC は存在確認をせず、開けなければ理由を通知（場所は通知に入れない）
- **行・カードに、リンクの数のバッジ**（外へ出る矢印のアイコンと数。添付のクリップとは別）。押すとリンクの節。載せて少し待つと、先頭 6 件（アイコン・表示名・場所を薄く）と「ほか N 件」のツールチップ。リスト・ガントの左の表・ボード
- **保存**: `project.settings.json` の `"links"`（Issue Id → `[{title, target, at}]`。空なら書かない）。1 課題 50 件・全体 5,000 件・表示名 200 バイトまで。同じ課題の同じ場所は追加しない（ファイルは大文字小文字と `\` `/` の違いを無視）。読み込みでは、型・Issue Id（`isSafePathComponent` を通り 64 バイトまで）・開けない場所・重複・件数超過の壊れた値は読み飛ばし、表示名が壊れていれば既定の名前、`at` が壊れていれば 0 にして項目は残す。項目の未知のキーは `extra` に保持して書き戻す。**CSV は変えない**（golden はそのまま一致）。**共有・バックアップの JSON には入れない**（パスは環境依存）。課題を削除してもリンクは残り（Undo で戻せる）、その Issue Id は新しい課題に使い回さない（`nextIssueId`）。リンクの追加・削除は元に戻す（Undo）の対象外
- **URL・パス・表示名はログに出さない**（通知にも件数と理由だけ）
- 暫定判断は docs/spec-questions.md の B43。入れていない: ブラウザのアドレスバー・`.url` のドラッグ＆ドロップ（OLE が要る。貼り付けのみ）、GitHub の PR・Issue の状態確認（#61）、リンク切れの検査（存在確認をしない方針）、バックアップ・共有 JSON へのリンクの同梱。Windows の実機での UNC・長い（260 文字を超える）パス・日本語パスの確認は未（Linux の煙テストとスクリーンショットでの確認）
- 単体テスト（`tests/unit/test_links.cpp`: 判定の表・許可リスト・難読化・長さの上限・表示名・実行ファイルの判定・親フォルダ・重複・上限・移動とコピー・貼り付け・保存の往復・壊れた値・未知のキー・5,000 件・共有 JSON に入らないこと・コントローラ）、UI の煙テスト（追加・断る・貼り付け・クリックで開く・実行ファイルの警告・右クリック・編集・削除・並べ替え・ドラッグ・バッジ・ツールチップ・ダーク・平置き）、スクリーンショット（ライト・ダーク）を足した

### GitHub の PR・Issue のリンク
- **GitHub の PR・Issue のリンクの状態を確認し、閉じたら課題を完了にする提案**（#61。#60 のリンクの上に載る）。`https://github.com/<owner>/<repo>/pull/<n>` と `/issues/<n>` のリンクは専用のアイコン（`LinkKind::GitHubPull` / `GitHubIssue`。Web として開けることは今までどおり）。URL の検証は `core/github_ref`（`parseGitHubUrl`）: 許可は github.com の PR・Issue だけで、末尾の `/`・`?…`・`#…`・下位パス（`/files` など）は正規化して許容、`http://`・`www.`・別ホスト（`github.com.evil.example`）・ユーザー情報・ポート・`..`・エンコードされた区切り・空白／制御文字・長すぎる owner／repo・不正な番号は断る
- **「GitHub の状態を確認」**（添付タブのリンクの節。その課題の GitHub のリンクを順に確認）と、右クリックの「状態を確認」（そのリンクだけ）。状態は `open` `draft` `merged` `closed（マージなし）` `closed（完了）` `closed（計画外）` のラベルと確認した日時で出す（色だけに頼らない）。確認中は「確認中…」、失敗は理由を通知（URL・リポジトリ名は出さない）して課題は変えない。**確認は押したときだけ**（起動時の自動確認・定期通信はしない）。結果は**メモリ上のみ**（保存しない。起動のたびに未確認）
- **取得は `gh`（GitHub CLI）だけ**（トークン方式は後回し）。取得の窓口は `IRemoteStatus`（時計・ファイルと同じ流儀で差し替えられる。テストは固定の応答）。Windows の実装（`app/platform/win32_gh.*`）は `gh.exe` を `CreateProcessW` で**直接**起動し（シェルを通さない）、検証済みの URL を 1 つの引数として渡し、15 秒で打ち切り、出力は 64KB まで。UI を固めないよう別のスレッドで 1 件ずつ実行し、結果をフレームごとに拾う
- **すべて閉じたら完了の提案**: その課題の GitHub のリンクがすべて閉じている（open／draft／失敗／未確認が 1 件もない）ときだけ、通知「#N 『件名（先頭 30 文字）』のリンクがすべて閉じています。完了にしますか？」と「完了にする」ボタン（確認ダイアログにはしない）。マージなしで閉じた PR・計画外で閉じた Issue を含むときは文に明記。押すと状況が完了（Done）になり、`Resolved` に閉じた日（最も遅い日。マージした PR はマージ日）が入り、**Undo 1 回で戻る**。了承しなければ課題は変わらない

- **行・カードの添付バッジにマウスを載せると、サムネイルのツールチップ**（#19 の残り）: リストと、ガントの左の表の行、ボードのカードのクリップのバッジ（アイコンと数）に少し待ってマウスを載せると、添付の先頭 4 件ぶんを出す。画像は小さなサムネイルを横に並べ、画像でないものは名前だけ、5 件目以降は「ほか N 件」。サムネイルは添付タブ・ドラッグと同じテクスチャのキャッシュを使い（デコードは 1 フレームに 1 枚まで。まだなら枠とアイコン）、マウスを載せていないときは画像を読まない。添付のドラッグ中は出さない
- **添付のメタ情報に SHA-256**: 追加（ドロップ・ファイルを選んで追加・貼り付け・コピー）のときに、書いた本体と同じバイト列から SHA-256 を計算し、`project.settings.json` の添付のメタ情報に `sha256`（16進小文字 64 文字）として保存する。移動は引き継ぐ（本体を読み直さない）。添付タブの項目にマウスを載せると先頭 12 文字を `SHA-256: 0123456789ab…` と短縮表示する（「ハッシュをコピー」はつけない）
- 古いメタ情報（`sha256` のないもの）は壊さず、空（不明）として扱い、書くときも出さない（既存の設定ファイルは変わらない）。長さ・文字・型の壊れた値は読み飛ばして空にする（項目は消さない）
- SHA-256 は依存を足さずに `core` に自前で実装（`sha256.hpp`。RFC 6234。少しずつ食わせられる `Sha256` と、まとめて計算する `sha256Hex`）。50MB のファイルも、追加のために読む `IFileStore::read` のバイト列にそのまま掛けるので、追加の読み込みはない（UI スレッドで同期的。B40）
- `AppController` などの呼び出し側は変更なし。`Attachment` に `sha256` が増えたので、波括弧で組み立てているテストの初期化子に 1 つ足した
- 入れていない: バックアップへの添付の同梱、エクスプローラーへの取り出し、PNG への変換、ハッシュのコピー・照合（付けたあとにファイルが変わっても値は更新しない）。Windows の実機でのホバーの表示は未確認（Linux の画面キャプチャでの確認）
- 単体テスト（RFC 6234 のテストベクタ `abc`・空・448 ビット・100万個の `a`、パディングの境目、分割して食わせても同じ値、`isSha256Hex`、追加・データ・コピー・移動での値、設定 JSON の往復と古い形式、壊れた値、50MB）、UI の煙テスト（載せていないときは読まない・載せると先頭 4 件のうち画像だけを読む・外すと消える・ボードでも出る・項目の詳細の有無）、スクリーンショット（リスト・ボードのツールチップ・SHA-256 の詳細）を足した

## 0.3.0（2026-10-20）

### 拡大縮小
- 画面全体: `Ctrl+ホイール`（タッチパッドのピンチも同じ）・`Ctrl+「+」「-」`・`Ctrl+0`（100%に戻す）。70〜200% の9段階で、変えた値は設定ファイルに保存する。変えた直後に倍率を画面の上に出す。アプリの設定にも「-」「+」「100%に戻す」を置いた
- ガントの時間軸: 時間軸の上で `Ctrl+ホイール` を回すと、1日の幅を連続して変える（0.9〜40px）。マウスの位置の日付が動かない。日・週・月・全体のボタンを押すと段階に戻る。幅は保存しない（JS版と共有する設定に、JS版が知らない値を書かないため）

### 配布
- インストーラ版（`ProjectRoadmap-Setup-<版>.exe`。Inno Setup）を CI で作り、リリースに付ける。既定は管理者権限なし（`%LOCALAPPDATA%\Programs\ProjectRoadmap`）、「すべてのユーザー」も選べる。日本語・英語の画面、スタートメニューとデスクトップのショートカット。上書きインストールで更新でき、アンインストールしても `data\projects` と `roadmap_prefs.json` は残す。CI で無人のインストール・上書き・アンインストールまで確かめる
- ポータブル版の zip はこれまでどおり

## 0.2.0（2026-10-20）

### 画面
- 上のバーの絞り込み（担当・状況・優先度・「遅れ」「余裕小」のチップ）は、一致しない課題を消さずに薄く表示する。検索語はこれまでどおり隠す
- 表の列名（課題・種別・状況・担当・優先度・余裕）の右に漏斗を置き、値のチェックで列ごとに絞り込む（一致しないものは隠す）。件名は文字で絞り込む
- 行（ボードはカード）にマウスを載せると、ごみ箱のボタンが出る。押すとすぐ削除し、通知の「元に戻す」で戻せる
- 「アプリの設定」（`…` メニュー・`Ctrl+,`・コマンドパレット）: 保存先の変更と既定に戻す（今のプロジェクトのコピーを選べる）、テーマ・密度・文字の大きさ（90〜150%）・絞り込みで薄くする濃さ、自分の名前、削除の前の確認、ヒントをもう一度表示、設定ファイルの場所。テーマと密度はプロジェクト設定からこちらへ移した
- アプリの設定に「プロジェクトを開いたら基準日を今日に合わせる」（起動中、プロジェクトごとに1回。前の日付は通知に出す）
- データフォルダを監視し、Excel などで CSV を保存・追加したら、ウィンドウがアクティブでなくても0.5秒後に取り込む（編集中は終わるまで待つ）
- 「N」で行を追加した直後など、入力欄がアクティブになる前に打った文字も落とさない（B13）
- 「削除の前に確かめる」をオンにすると、ごみ箱・Delete キー・メニューの削除で確認ダイアログを出す（子の件数も表示）

### 配布
- ポータブル版のフォルダ構成（exe・`data/projects/`・`samples/`・`README.txt`）を `cmake --install --component portable` で作る。CI の成果物とリリースの zip もこの形

### CI・依存
- Windows（MSVC）のビルドが通るように直した（CMake 4 と doctest、`windows.h` の `max`）。警告をエラーにし、UI の煙テストも動かす
- doctest を 2.5.3 に更新（CMake 4 で警告なく構成できる。テストだけで使う）
