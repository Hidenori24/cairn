# 変更履歴

## 0.7.0（未リリース）

### 添付
- **行・カードの添付バッジにマウスを載せると、サムネイルのツールチップ**（#19 の残り）: リストと、ガントの左の表の行、ボードのカードのクリップのバッジ（アイコンと数）に少し待ってマウスを載せると、添付の先頭 4 件ぶんを出す。画像は小さなサムネイルを横に並べ、画像でないものは名前だけ、5 件目以降は「ほか N 件」。サムネイルは添付タブ・ドラッグと同じテクスチャのキャッシュを使い（デコードは 1 フレームに 1 枚まで。まだなら枠とアイコン）、マウスを載せていないときは画像を読まない。添付のドラッグ中は出さない
- **添付のメタ情報に SHA-256**: 追加（ドロップ・ファイルを選んで追加・貼り付け・コピー）のときに、書いた本体と同じバイト列から SHA-256 を計算し、`project.settings.json` の添付のメタ情報に `sha256`（16進小文字 64 文字）として保存する。移動は引き継ぐ（本体を読み直さない）。添付タブの項目にマウスを載せると先頭 12 文字を `SHA-256: 0123456789ab…` と短縮表示する（「ハッシュをコピー」はつけない）
- 古いメタ情報（`sha256` のないもの）は壊さず、空（不明）として扱い、書くときも出さない（既存の設定ファイルは変わらない）。長さ・文字・型の壊れた値は読み飛ばして空にする（項目は消さない）
- SHA-256 は依存を足さずに `core` に自前で実装（`sha256.hpp`。RFC 6234。少しずつ食わせられる `Sha256` と、まとめて計算する `sha256Hex`）。50MB のファイルも、追加のために読む `IFileStore::read` のバイト列にそのまま掛けるので、追加の読み込みはない（UI スレッドで同期的。B40）
- `AppController` などの呼び出し側は変更なし。`Attachment` に `sha256` が増えたので、波括弧で組み立てているテストの初期化子に 1 つ足した
- 入れていない: バックアップへの添付の同梱、エクスプローラーへの取り出し、PNG への変換、ハッシュのコピー・照合（付けたあとにファイルが変わっても値は更新しない）。Windows の実機でのホバーの表示は未確認（Linux の画面キャプチャでの確認）
- 単体テスト（RFC 6234 のテストベクタ `abc`・空・448 ビット・100万個の `a`、パディングの境目、分割して食わせても同じ値、`isSha256Hex`、追加・データ・コピー・移動での値、設定 JSON の往復と古い形式、壊れた値、50MB）、UI の煙テスト（載せていないときは読まない・載せると先頭 4 件のうち画像だけを読む・外すと消える・ボードでも出る・項目の詳細の有無）、スクリーンショット（リスト・ボードのツールチップ・SHA-256 の詳細）を足した

## 0.6.0（未リリース）

### 添付
- **サムネイルをつかんで、別の課題へ移動・コピー**（#19 の残りの受け入れ条件）: 詳細パネルの「添付」タブの行（サムネイル・アイコン・名前のどこでも）を押して動かすと、カーソルに小さなサムネイルと名前が付き、受けられる課題（リストの行・ガントの行・ボードのカード・詳細パネル）が縁取られる。別の課題の上で離すと**移動**、Ctrl を押しながら離すと**コピー**。何もないところで離す・Esc（ボタンを離すのと同じフレームでも先に見る）・ダイアログ／コマンドパレット／ポップアップを開く・プロジェクトを切り替えると、何もせずに取り消す（モーダルの裏では動かさない）。ドロップ先の判定は、エクスプローラーからのドロップと同じ（前のフレームに描いた `dropTargets`）。動かさずに押して離しただけなら、今までどおり画像のプレビュー
- 同じ課題の**添付の一覧の中でつかんで離すと並べ替え**（挿入位置に線が出る。並びも保存する。スクロールで隠れた行・一覧の見える範囲の外では並べ替えない）
- `core` に `moveAttachment` / `copyAttachment` / `reorderAttachment`（`IFileStore` 経由）。移動は本体を先に移し、移せなければメタ情報に触れない（食い違わせない）。同名は連番。コピーは新しいファイルとして、1ファイル・プロジェクト合計の上限を、実際に読めた大きさで検査し、日時と作成者は「いま付けた」ものにする。自分自身・存在しない課題・本体がない添付は理由を出して断る。移動・コピー先の Issue Id は、設定 JSON の読み込み（`isSafePathComponent`）を通る名前だけ（区切り・`..`・予約文字などを含む ID は、ファイルを動かす前に断る。保存→読み直しでメタ情報が消えないように）
- 「**ファイルを選んで追加**」ボタン（添付タブ）: `IPlatform::pickOpenFiles`（Win32 は `IFileOpenDialog` の複数選択）。ダイアログは描画が終わってから開く
- **クリップボードの画像の貼り付け**: 課題が 1 つ選ばれていて、クリップボードにテキストがなく画像があるとき、入力欄の外の `Ctrl+V` で `貼り付け-<日時>.bmp` として添付する（テキストがあれば今までどおり子課題の貼り付けが先）。`IPlatform::clipboardImage`（Win32 は `CF_DIBV5` → `CF_DIB`）。BMP のヘッダの組み立てと検査（大きさ 0・極端な大きさ・知らない形式・画素や色表の欠け。サムネイルに使う stb_image が読める BI_RGB と BI_BITFIELDS だけ通し、RLE・BI_ALPHABITFIELDS などは理由つきで断る）は `core` の `bmpFromDib` にあり、Linux でも試せる
- **サムネイルの大きさのスライダー**（添付タブ。24〜160。プロジェクトの `ui` 設定の `attachThumb` に覚える。範囲外・数値でない値は既定に戻す）
- 添付タブに、画像を貼り付けられる旨の案内と、つかんで動かせる旨の説明を足した
- `AppController::uiInt` が、範囲外の数値（設定 JSON）を `int` にキャストして未定義動作にならないよう、範囲外なら既定を返す
- 入れていない: エクスプローラーへのドラッグでの取り出し・ドロップ中のハイライト（どちらも OLE が必要）、SHA-256、バックアップへの添付の同梱、行・カードのホバーでの小さなサムネイル。Windows の実機では、`IFileOpenDialog`・クリップボードの画像（`CF_DIB`/`CF_DIBV5`）・つかんで動かす操作が未確認（コンパイルまでの確認）
- 単体テスト（移動・コピー・連番・失敗時の巻き戻し・上限・存在しない課題・自分自身・パスの安全・並べ替え・DIB → BMP の検査・コントローラ）、UI の煙テスト（ドラッグで移動・Ctrl でコピー・ドロップ先がない場所では何もしない・並べ替え・Esc・ドラッグ中に先の課題が消える・スライダー・ファイルを選んで追加（スタブ）・クリップボードの画像（スタブ））、スクリーンショット（添付タブ・ドラッグ中・サムネイルを大きくした一覧）を足した
### 依存
- **一覧の行・ボードのカードでも、ハンドルのドラッグで依存をつなげる**（#8 の残り。ガントは 0.4.0）。行・カードにマウスを載せると左右にハンドルが出る。右のハンドル → 別の行・カードへ = つかんだ課題が先行、左 = 後続。ゴムひも・つなぐ相手の強調（つなげない相手は赤で理由）・日程への影響（「N営業日 遅れます」）・離すと確定（Undo 1回）・Esc か元の場所で離すと取り消し、はガントと同じ。ドラッグ中にビューを切り替えたら終わる。依存の選択モード・ダイアログ・その場編集の間は出さない
- 一覧は表の左右に余白（20px）を取り、ハンドルはそこに出す（行のボタン・開閉と重ならない）。ボードはカードの左右の縁に出し、右下の削除ボタンと重ならない大きさにした。ハンドルを押したときは行・カードの選択にも、ボードの列の移動にもならない
- ドラッグ中に、見えている範囲の端（上下・左右）へマウスを近づけると自動でスクロールする（ガント・一覧・ボード）
- ガントの `linkDrag` の状態・ハンドルとゴムひもの描画・相手の判定と日程の影響・確定を `app/ui/link_drag.cpp` に切り出し、3 つのビューで共有した（ガントの見た目・挙動は変えていない）
- 煙テスト（一覧・ボードそれぞれで、両方向・Undo 1回・循環と重複・元の場所と Esc・選択やカードの移動と混ざらない・選択モード中とダイアログ中は出ない・ビュー切り替え・自動スクロール）と、画面（ホバー・ドラッグ中・不可の赤。ライト・ダーク）を足した

### 課題の作成
- アプリの設定に「課題を追加したとき、親や直前の兄弟の値を引き継ぐ」（既定はオフ = 今までどおり）。「子を追加」は親から、「同じ階層に追加」は直前の兄弟から、担当者・優先度・ラベル・期限（兄弟からは種別・期間も）を項目ごとに選んで引き継ぐ。種別は設定に関わらず階層で決まる。追加直後の通知「親から引き継ぎました（元に戻す）」から、追加ごと Undo 1回で戻せる。担当者を引き継ぐと担当者ごとの負荷が偏るので、設定の説明に注意を書いた
- 親の名前が見えない場面で、祖先のパス（`A › … › B`。長いときは真ん中を省略）を薄く出す: その場編集中の入力欄の上、並べ替え中の平らな一覧の件名の右（行の高さは変えない）、詳細パネルの見出し（これまでどおり押すとその課題へ移動。長いときは真ん中を「…」にしてマウスを載せると全体を出す）
- アプリの設定に「新しい課題の名前」を追加: 今のまま（既定）／親の名前＋連番（`要件定義の子 3`）／親の名前／既定名／自由入力（`{親}` `{親ID}` `{n}` `{日付}`）。入力欄に最初から入り、追加直後の Enter（次の行）でも付く。連番は兄弟の名前と重ならない。最上位は `新しい課題 n`。設定は `roadmap_prefs.json` の `newNameFormat`・`newNameCustom`
- 親の課題を1つ選んで `Ctrl+V`（入力欄の外）: クリップボードの複数行を、子課題としてまとめて作る。階層はインデント（タブ・空白・全角スペース・`- `・番号付きの箇条書き）で決め、タブ区切り（Excel）は1列目を件名にする。確認のプレビュー（件数・階層・先頭の12行・丸めた箇所の警告）を出し、上限は500行、Undo 1回で戻る。コマンドパレットからも使える

### 統計ビュー
- 5つ目の表示「統計」（キー `5`・コマンドパレット）。進み（期間ベース）・作業の件数・遅れ・余裕小・完了の見込み・担当なし、状況の積み上げ棒、余裕の分布、週ごとの完了（過去は完了日、先は最早の完了日）、担当別、ルート課題別、優先度別。絞り込みには従わず、プロジェクト全体を数える。担当別の行を押すと、その担当者の作業をリストで開く
- 集計は `core/stats`（UI に依存しない）。単体テストを足した

### 雛形
- 新しいプロジェクトと「はじめに」に「組込みソフトウェア開発の雛形」（要求・企画 → システム設計 → 詳細設計・実装・単体テスト → 結合・システムテスト → リリース・量産移管。42件、マイルストーン4つ。日付は持たず、作った日を基準に積む）。実行ファイルに埋め込む。件名・期間・依存は自分のプロジェクトに合わせて書き換える

### 依存
- 詳細パネルの「依存関係」タブの入力欄に候補一覧を出す（表示ID・キー・件名の部分一致。完全一致 → 最近つないだ課題 → 同じ階層の課題を先頭に）。クリック、または ↑↓ と Enter で選ぶ。追加済み・自分は出さず、循環になる相手と親子は理由つきで選べない表示にする
- 「画面で選ぶ」ボタンと、右クリックメニューの「先行にする…」「後続にする…」で、一覧・ガント・ボードの行（カード・バー）をクリックして相手を選ぶモードに入る（Esc か「中止」で抜ける）。つなげない相手は理由を通知して続ける。Undo 1回で戻る
- 複数選択して、右クリックのメニューと選択バーの「順につなぐ」「つなぎを外す」。画面の表示順（一覧・ガント・ボードのどこからでも）に A→B→C と終了→開始でつなぐ。親子の両方を選んだときは親だけ数える。すでにあるつなぎは足さず、循環になるときは何も変えずに理由を通知する。1回の Undo で戻る（ショートカットキーはなし）
- ガントのバーにマウスを載せると左右の端にハンドルが出る。右のハンドルから別のバーへドラッグで後続、左なら先行。ゴムひも線・吸着・つなげない相手（循環・重複・親子）は赤で理由・日程への影響のゴースト（「◯が N営業日 遅れます」）。離すと確定（Undo 1回）、空きで離すか Esc で取り消し（#8）
- 依存の矢印: ホバーで強調（「A → B」）・衝突（後続が先行の完了より前）は赤の点線・「依存 ▼」から「たどる」（選んだ課題の先行・後続以外を薄くする）と「クリティカルを強調」・矢印をつかんで付け替え、バーのない場所で離すと削除（#10）
- リストとガントの左の表に任意の「先行」列（設定でオン・オフ。既定はオフ）。ダブルクリックで表示 ID をカンマ区切りで入力し、存在しない・あいまい・重複・自分自身・親子・循環は赤で理由を出して確定しない。差分だけを反映（Undo 1回）、並べ替え・列の漏斗に対応（#9）
- 詳細パネルの「依存関係」タブの下に、Blocks 以外のリンク（Relates など）を「日程には影響しません」として表示・追加・削除（値は今までどおり知らない列に入るので、CSV の往復は変わらない）（#12）

### 保存（フォルダ構成）
- 新しいプロジェクトは `data/projects/<名前>/project.csv`・`project.settings.json`・`バックアップ/` で作る（CSV のバイト列は同じ）。削除は `_削除済み/<名前>.<日時>/` へフォルダごと。バックアップの30個はプロジェクトごと。フォルダの監視は1段下まで
- 以前の平置きは動かさず、そのまま読み書きできる。「データフォルダ」と「アプリの設定」の「フォルダ構成に移す」で、移す前に全ファイルを控え、バイト列を変えずに写して確かめてから元を消す（失敗したら元を残す）（#24）

### 添付
- 課題にファイル・画像を付ける。置き場は `<プロジェクト>/添付/<Issue Id>/`。詳細パネルの「添付」タブ（一覧・開く・削除・使用量）、行・ガント・カードにクリップと数。エクスプローラーから課題の行・カード・詳細パネルへドロップで添付、何もない場所は今までどおり CSV の取り込み。1ファイル 50MB・合計 1GB まで。削除は `_削除済み/<Issue Id>/` へ。実行ファイルは開く前に警告
- PNG・JPEG・GIF・BMP のサムネイルとプレビュー（`stb_image` 2.30 を `third_party/stb` に同梱。パブリックドメイン／MIT・ヘッダ1つ・ネットワークなしでもビルドできるため）。JIRA の Attachment 列は、取り込み・書き出しで壊さず、添付タブに「本体はありません」と表示（#19）
