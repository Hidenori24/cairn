プロジェクト管理
=======================
使い方: index.html をブラウザ（Chrome / Edge）で開くだけです（サーバー不要）。
データの原本はJIRA互換のCSVです。

[データの保存 ― 作業フォルダ（おすすめ）]
右上の「ブラウザ内のみ」をクリック →「フォルダを選ぶ」で、data/projects などの専用フォルダを1回選びます。
以降は、編集するたびに自動で次の2ファイルを書き込みます（保存ボタンは不要。右上に最終保存時刻が出ます）。
  プロジェクト名.csv            JIRA互換の原本（Excelなどで開いて編集してもOK。アプリに戻ると反映されます）
  プロジェクト名.settings.json  基準日・休業日・シナリオ・表示など、CSVに入らない設定
フォルダごとUSBやクラウドに入れて持ち運べば、別のPCでも同じ内容で開けます。
  - 上書きする前のCSVは、そのセッションの最初の1回だけ「_バックアップ」に残します。
  - 削除したプロジェクトのファイルは「_削除済み」に移します（戻せます）。
  - ブラウザを開き直すと、書き込みの許可を求められることがあります（上部の「許可して再開」）。
  - 「ドキュメント」「デスクトップ」「ダウンロード」そのものはブラウザの制限で選べません。その中のサブフォルダを選んでください。
  - フォルダを選ばない場合は、これまで通りブラウザ内（localStorage）だけに保存します。ブラウザのサイトデータを消すと消えます。
  - 手を付けていないサンプルは、フォルダには書き出しません。
  - CSVはBOMなしUTF-8で書きます。ExcelでCSVを直接開くと文字化けすることがあるため、Excelから開くときは「データ→テキストまたはCSVから」でUTF-8を指定してください。
手動の「CSVを取り込む」「書き出し」も使えます（JIRA用の書き出しなど）。

[絞り込み]
ツールバーの「担当者」「状況」「優先度」と、上部の検索・遅れ/余裕小のチップを組み合わせて絞り込めます（すべてAND条件）。
担当者は「未割当」「担当者あり」も選べます。担当者の一覧は、そのプロジェクトの課題に入力された担当者名から自動で作られます（別に名簿はありません）。
ガント・ボード・リストで同じ条件が効きます。「絞り込み解除」で全部戻ります。

[課題の番号（B-1 や 100 の違い）]
一覧に出る番号は、次の優先順位で決まります。
  1) 件名の先頭の [B-1] のような部分（番号タグ）
  2) JIRAのIssue key（DEV-100 など。プロジェクトのキーを設定していれば、新しい課題に自動で付きます）
  3) 内部の連番（100 など）
詳細パネルの「番号（表示用ID）」で変更できます（空にすると 2→3 の表示に戻ります）。同じ番号は重複して使えません。
番号タグは件名の一部としてCSVに保存されるので、JIRAに出すときも「[B-1] 件名」のままになります。

フォルダの構成
  index.html            入口（これを開く）
  css/                  見た目
    style.css
  js/                   ブラウザで動くプログラム
    app.js              画面（src/ をまとめたもの。直接は編集しない）
    lib/                画面に依らない部品
      sched.js          営業日カレンダー
      csvio.js          CSVの読み書き（JIRA互換）
      engine.js         スケジュール計算（最早・最遅・余裕・工数制約）
      store.js          プロジェクトの保存（ブラウザ内）
      sample.js         初回に入るサンプル
  data/                 データ（CSV）。アプリが読む原本はここに置く
    projects/           実際のプロジェクトの原本CSV（例: example_project.csv）
    samples/            サンプル（regulation_roadmap.csv・hierarchy_demo.csv）
  src/                  画面のソース（React）
    main.jsx  App.jsx
    core/               状態・操作・計算との橋渡し（core.js state.js actions.js）、作業フォルダの読み書き（folder.js）
    views/              ガント・ボード・リスト・ギャップ
    panels/             詳細パネル・ダイアログ・コマンドパレット
    components/         共通の部品（ui.jsx cells.jsx）
  tools/                開発用（利用には不要）
    build.sh            src/ から js/app.js を作る（初回は tools で npm install）
    package.json
    jira_check.py       JIRA取り込み用CSVの互換チェック（python3 tools/jira_check.py）

作業フォルダを選んでいない場合、data/ のCSVはブラウザの制約でアプリが自動では読みません。「CSVを取り込む」で選んで読み込んでください。

[ギャップ表示]
上部タブ「ギャップ」(キー 4)。種別が Milestone の課題を「ゴール」として、期限(理想)と見込み(現状)の差、
いま日程を決めている未完了タスクの連なり、並行して必要な前提を表示します。優先度 Highest のゴールが先頭に出ます。

[テンプレート(子タスクの雛形)]
課題の右クリック／複数選択バーの「テンプレ」／Ctrl+K から「テンプレから子タスクを追加」。複数の課題へまとめて追加でき、取り消しは1回で戻ります。
追加された子は通常のサブタスク(Parent・Blocksリンク)なのでCSVの形式は変わりません。番号タグ [B-1] があれば [B-1-1]… と続けて振ります。
子タスクを持つ課題を右クリック →「この子タスクをテンプレとして保存」で自分用の雛形を作れます(このブラウザ内に保存。共有JSON・バックアップにも含まれます)。

[階層とJIRA]
原本(app形式)のCSVは Parent 列で何階層でも持てます。JIRA用に書き出すときだけ、JIRAの標準（Epic > タスク > サブタスク の3段、サブタスクの下に子は作れない）に合わせます。
  - タスクより深い課題は、上のタスク直下のサブタスクにし、間にあった課題名を説明の先頭に「[元の階層] …」と残します。
  - 種別に標準が無い Milestone は Task（Epicの下はTask、それ以外もTask階層）にして Milestone ラベルを付けます。取り込み直すとマイルストーンに戻ります。
  - 見積は 1w・3d・12h のような整数の書式、日付は yyyy-MM-dd（取り込みの日付形式にこれを指定）、ラベルに空白は入れません。
  - アプリ独自の列（Earliest start・Deadline・Remaining (weeks)・Duration (weeks)）は末尾に足すだけです。取り込み時は「対応づけない」で読み飛ばせます。
